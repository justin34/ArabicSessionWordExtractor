# Arabic Session Word Extractor — Domain Context

A desktop app that listens to spoken Arabic (class, videos), shows a live visual transcript with English glosses, and builds a growing vocabulary with auto-generated study guides.

## Glossary

- **Session** — one recording run (a class, a video). Owns one Transcript and one or two audio tracks: a **Desktop Track** (always transcribed) and an optional **Mic Track** (separate file; transcribed only when the learner asks).
- **Transcript** — ordered list of Utterances for a Session, with timings. One per Session, holding the Utterances of both tracks.
- **Utterance** — one sentence/segment of speech: Arabic text, sentence translation (English), start/end time, its Tokens, and the **Track** (Desktop or Mic) it was heard on.
- **Learner Utterance** — an Utterance from the Mic Track: the learner's own speech. Translated but never analyzed, so its words have no gloss, no Lemma and no word panel, and it never feeds the Vocabulary, Word Cards, Session Guide or Anki export (a mispronounced word is not a study word).
- **Token** — one word occurrence in an Utterance: surface form, time span, per-word English gloss, link to a Lemma.
- **Foreign word** — a Token whose letters are not all Arabic (e.g. an English word the teacher says, or an Arabic prefix on a Latin word like الiPhone). Part of the Transcript, never of the Vocabulary: no Lemma, gloss or Word Card.
- **Surface form** — the word exactly as heard/written (e.g. كَتَبُوا).
- **Lemma** — dictionary form a Token resolves to. **This is the unit of the Vocabulary.** Surface forms heard are tracked on the Lemma.
- **Vocabulary** — the global, append-only set of Lemmas the learner has heard, with first-heard date, occurrence count, and the Sessions/Utterances where each appeared.
- **Word Card** — per-Lemma study guide, auto-generated from Detail Modules.
- **Session Guide** — per-Session study guide: new Lemmas, grouped, linking to their Word Cards.
- **Detail Module** — a pluggable unit that contributes one section of word info (e.g. definition, root, conjugations, example sentences from the learner's own Sessions). Modules can be added/removed/reordered without touching the rest of the app. Used by the click-a-word panel and Word Cards.
- **Session List** — the home screen: past Sessions, and the entry point to start a new one. Opening a completed Session shows its Replay View; opening a recording Session shows its Live View.
- **Live View** — the recording screen: Arabic (RTL) with English gloss under each word, plus a sentence translation line.
- **Demo Session** — a developer-only Session fed by a scripted fake transcript, kept in memory and never stored. Shown with a Demo badge; hidden in packaged builds.
- **Replay View** — plays a Session's audio while highlighting the current Token/Utterance, same visuals as Live View.

## Decisions (v1)

| Area | Decision |
|---|---|
| Platform | Desktop app (Electron or Tauri); can capture mic and, later, system audio |
| STT | Cloud streaming API behind a swappable provider interface |
| Language | Arabic → English only, hardcoded. **MSA (Fusha) only** |
| Vocabulary unit | Lemma; surface forms tracked |
| Translation | Word-level gloss and sentence-level, both |
| Vocabulary (#7) | Each final Utterance is analyzed once its translation is in (see Ambiguity (#20)), never holding up the next one; a failed analysis leaves that Utterance's words out of the Vocabulary. A Lemma is identified by the analyzer's diacritized dictionary form (`lex`), one row per spelling. Every analyzed word with a letter is an occurrence: the count is occurrences across all Sessions, first heard is the wall-clock time its Utterance went final, and each new surface form (punctuation stripped) is added to the Lemma. Analyzed words are matched to the timed Tokens by their letters, so each Token links to its Lemma. The Vocabulary screen searches the Lemma, surface forms, root and English stem gloss, ignoring diacritics, hamza on alef, ى/ي, ة/ه and case |
| Quick gloss (#8) | Each word in Live View shows a short English gloss under it once its Utterance is analyzed, stored on the Token. It is the bundled dictionary's first sense of the word's Lemma: its first comma/semicolon alternative without parenthesised qualifiers, or the shortest when that one is over 16 characters (a verb keeps only its "to …" alternatives). CAMeL's stem gloss (first alternative, clitic and bracketed parts dropped) is used instead when the dictionary has no fitting entry, when the dictionary's gloss is over 24 characters, and for prepositions, conjunctions, particles and interjections, which Wiktionary describes ("introduces a yes-no question") rather than translates ("does"). A Lemma matches the entry spelled with the same letters whose diacritized headword equals CAMeL's `lex` (ignoring the final short vowel, sukun, and fatha before a long alef) and whose part of speech fits; failing that, the sole entry of that spelling with a fitting part of speech. A proper name only matches a Wiktionary name. A failed lookup falls back to the stem gloss |
| Word panel (#9) | Clicking a word in Live View opens a side panel built from Detail Modules, for the word's Lemma and the surface form clicked. Built-in modules, in default order: `form` (dictionary form, form heard, part of speech, root, pattern), `pronunciation` (CAMeL CAPHI of the form heard), `definitions` (all Wiktionary senses, up to 8, and the etymology), `examples` (up to 3 Tatoeba sentences containing the Lemma or a heard surface form as a whole word, shortest first), `own-examples` (up to 5 Utterances from the learner's Sessions, never Learner Utterances, most recent first) and `sessions` (each Session heard in, with times heard). The modules shown and their order come from `detail-modules.json` in the app's data folder (a JSON array of module ids; not on the settings screen yet); without it all built-ins show. A module with no data, one that throws, and one that has not answered in 5 s are left out; so is a section the panel cannot render. A word whose Utterance is not analyzed yet opens the panel with a note instead of details |
| Study guides | Word Cards and Session Guides; **read-only** (no SRS/quizzing in v1). Spaced repetition is left to Anki, through an export (see Anki export (#31)) |
| Anki export (#31) | One-way and stateless: the app writes a `.apkg` and keeps no record of it, reading nothing back from Anki, which owns all scheduling. "Export to Anki" on the Vocabulary screen exports every Lemma; on a Session Guide, that Session's new Lemmas; no hand-picking. One note per Lemma, of the note type "Arabic Session Word Extractor — Arabic Word", into the deck "Arabic Session Word Extractor - Vocabulary", both with fixed ids (new ones from the rename to Arabic Session Word Extractor, planned in #36, which also changed every note's GUID: decks imported before it duplicate rather than update). The fields are fixed whatever `detail-modules.json` says: `Lemma` (sort field), `Gloss`, `Definitions` (up to 8), `PartOfSpeech`, `Root`, `Pattern`, `Pronunciation` (CAPHI), `FormsHeard`, `MyExample` and `MyExampleTranslation` (the most recent Utterance), `Example` and `ExampleTranslation` (the shortest Tatoeba sentence). One card per note, recognition only: the front shows the Lemma right to left and speaks it with `{{tts ar:Lemma}}` (the bare language code, so any installed Arabic voice can match; `ar_SA` alone found none on the learner's device), using the device's Arabic voice, which the app does not check for; the back speaks nothing. Tags: `pos::<part of speech>` and `session::<date first heard>`. A note's GUID is a hash of `lemmas.lemma`, so importing again updates notes instead of duplicating them. Its modification time is the Word Card's `updated_at` (else the first-heard time), so Anki overwrites the learner's own edits only when the app has rebuilt that card. A Demo Session has no export; an empty guide or Vocabulary disables the button; a failed export leaves no file. As built: a schema-11 Anki collection (`collection.anki2`, which every Anki since 2.1 imports) zipped by a small built-in writer, no dependency; the Save dialog suggests `arabic-vocabulary-<date>.apkg` or `session-<date>-new-words.apkg`, and the deck is written beside the chosen file and renamed into place. The Noto Naskh font is packaged as `_NotoNaskhArabic-Regular.woff2`, so cards show it without the font installed. `Pronunciation` is the CAPHI of a heard form spelled as the Lemma (كَتَبَ for كَتَب), empty when none was heard; `Example` is the shortest of three Tatoeba sentences; `pos::` tags use the readable part of speech with `_` for spaces (`pos::proper_noun`). The back repeats the Lemma instead of `{{FrontSide}}`, so it speaks nothing Audio clips (#32) and sentence cards (#33) are follow-ups |
| Study guides (#10) | Both are stored as generated (`word_cards`, `session_guides` in `app.db`). A **Word Card** is built from the same enabled Detail Modules as the word panel, without a form clicked, when its Lemma first enters the Vocabulary (alongside that Utterance's glosses, so a Session waits for it before it completes). When a Session ends, the Word Cards of every Lemma heard in it are rebuilt in the background, keeping when each was first generated, so "Your examples" and "Heard in" include that Session. A **Session Guide** is generated as the Session ends. It lists the Lemmas first heard in that Session (heard in no earlier Session), in the order heard, grouped as Nouns, Verbs, Adjectives, Adverbs, Names and Other words (by CAMeL part of speech). Each word shows the first quick gloss one of its Tokens got there (else its stem gloss) and the times heard there, and links to its Word Card. A guide is not regenerated later. When the app opens, any Lemma without a Word Card and any completed Session without a Session Guide (one a crash ended, or data from before #10) gets one. A card whose modules all fail is stored with no sections; a failure never stops the Session completing. Opening a completed Session shows its Replay View, with its Session Guide in a second tab; a Word Card opens from the guide or from the Vocabulary |
| Replay (#11) | Opening a completed Session shows two tabs, Replay (first) and Session Guide; Replay keeps playing behind the guide. Replay View plays the Desktop Track, which the main process serves from `session-audio://desktop/<session id>` with byte ranges so the player can seek; only stored Sessions' Desktop Tracks are served. The whole stored Transcript is drawn as in Live View, every word in its column even when it has no gloss (an Utterance whose analysis failed), and every Arabic word opens the word panel. Token timings are positions in the Desktop Track. The current Utterance is the one whose span holds the playback position; the current Token is the last of its words to have started, so a pause between words keeps the earlier one lit; between Utterances nothing is lit. Foreign words are lit like any other. Clicking a sentence, or its start time, seeks there and plays; clicking a word opens its panel without seeking. MediaRecorder's WebM carries no duration, so the seek bar falls back to the Session's length. A Session with a Mic Track plays it alongside (see Mic Track (#12)). A Demo Session has nothing to replay |
| Mic Track (#12) | The Start panel offers "Also record my microphone", unticked by default; the choice is per Session. When ticked, the microphone is opened before the Session is created (a failure starts nothing and says why), and both recorders begin together. Mic audio is appended to its own file, `session-<id>-mic.webm` beside the Desktop Track, and is fed to speech-to-text only when the learner asks, on its own stream (see Mic transcription). A Session without one stores no Mic Track (`mic_track_path` is null, as for Sessions stored before #12). Replay loads it from `session-audio://mic/<id>`, with byte ranges like the Desktop Track. The Desktop Track leads: play, pause and every seek are applied to the Mic Track too, and while playing it is moved back to the Desktop Track's position whenever it drifts more than 0.25 s. A Mic Track that cannot be played is left out with a note, and the Desktop Track plays alone |
| Mic transcription (#42 built; #43-#45 planned) | The learner's own speech can be transcribed as Learner Utterances, kept apart by Track (ADR 0004). **Live (#42):** the Start panel's "Also transcribe my speech", nested under the mic box, unticked by default, per Session, disabled without the mic box or a speech-to-text key, with a hint to use headphones or a mic threshold and that usage roughly doubles. The Mic Track gets its own speech-to-text stream, never one diarized stream. Learner Utterances are translated, never analyzed, and never feed the Vocabulary, Word Cards, Session Guide, the `own-examples`/`sessions` modules or Anki. Live View always interleaves them by start time, marked "You" with their own tint and no glosses. A mic stream that stops ends only mic transcription. Stored Utterances from before are Desktop. As built: each Utterance stores its Track (`utterances.track`, `'desktop'` by default, so older databases need no migration). The Mic Track's stream uses the same keyed speech-to-text as the Desktop Track's, opened when the Session starts; its start times count from the Mic Track's start, as the Desktop Track's do from its own, which is how Live View interleaves them (an Utterance goes before any that starts later). A Learner Utterance's words are still stored as Tokens with timings, with no gloss and no Lemma, and the store refuses to record them as heard; every reader of study material also counts only the Desktop Track. Live View's note reads "Transcription of your microphone has stopped", with the reason, beside the teacher's own note when that stream stops too. Until #43, Replay shows the teacher's Transcript only. **Replay (#43):** a Together · Separate switch in the completed Session's header, shown only when there are Learner Utterances, saved for all Sessions, Together by default. Together interleaves them in Replay; Separate gives three tabs, Replay (teacher) · My Speech · Session Guide, with one player keeping both Tracks playing across tabs. Each Track has its own lit Utterance. **Mic threshold (#44):** a slider with a live level meter in Settings → Audio, off by default, gating only what the mic sends to speech-to-text (never the recording), held open about 0.5 s after the level drops. **Afterwards (#45):** "Transcribe my microphone" in the completed Session's header, only for a Mic Track with no Learner Utterances, run once, through Soniox async (`stt-async-v6`) with Deepgram pre-recorded as fallback and the current threshold applied, in the background with a progress note; a failure keeps the button. A Session whose live mic transcription stopped partway is not repaired in v1. Bleed (the teacher heard through speakers) is mitigated, not prevented; detecting duplicates is not planned |
| Foreign words | A word is Arabic only when every letter is one of the 28 Arabic letters, a hamza form (ء أ إ آ ؤ ئ ٱ), ة or ى; diacritics and tatweel are allowed, digits are ignored. Any other letter (Latin, or پ چ ژ گ ڤ) makes it a Foreign word, mixed words such as الiPhone included. A Foreign word stays in the Transcript as heard, with no gloss and no click, and is still highlighted in Replay, but never enters the Vocabulary: no Lemma, occurrence, Word Card or Session Guide entry. An Utterance with no Arabic word is neither translated nor analyzed and shows no translation line; a mixed Utterance is translated as usual. When the app opens, any stored Foreign-word Lemma is deleted with its occurrences and Word Card, its Tokens are unlinked, and it is removed from stored Session Guides, leaving the rest of each guide as it was (the one exception to guides not being regenerated) |
| Word data | Dictionary / open data (modular per source), not LLM-generated |
| Storage | Local only: SQLite plus audio files on disk. No accounts |
| Lemmatizer | Python sidecar running CAMeL Tools (lemma, root, POS), bundled with the app |
| Ambiguity (#20) | One reading per Token, chosen in the sentence; no manual step in v1. camel-tools' MLE disambiguator, the only one that runs without torch, picks each word's reading out of context (found in #6), so the helper ranks all of CAMeL's readings of a word and brings the sentence in on top. (1) **MLE ranking**, with the MLE model's own reading matched by dictionary form, part of speech and diacritized form first: camel-tools' matching let feature values the r13 database writes differently outweigh the dictionary form, giving ليس "be valiant", لست "taste" and أيضا "metabolism". (2) **The sentence translation**: when the MLE pick's stem gloss shares no word with the English translation and another reading's does, that reading wins (رفع الجنود العلم, "raised the flag": عَلَم; اكتشف العالم, "the scientist": عالِم). Words are compared by a crude English stem, with common irregular forms (went → go) and without stopwords; a translation word the MLE pick of another word in the sentence already accounts for does not count ("very good": جيدة takes "good", so جداً is "very"). Function words (prepositions, conjunctions, particles, pronouns) and picks whose gloss is only stopwords (كان "was") are never changed. (3) **The word before**, when the translation says nothing: a bare perfect verb straight after a verb is read as a noun when it can be (قرأت كتب "I read books"), except after كان and its sisters. Clitics still tell readings apart (وكتبوا is a verb, فكتبها a noun). Analysis waits for the Utterance's translation up to 3 s, then goes on without it; a failed translation is analyzed without one. Measured on 1,500 Tatoeba pairs: 7% of words change reading, mostly fixes; 1.9 ms per sentence; no installer or startup cost. Rejected: CAMeL's BERT disambiguator predicts only grammatical features and breaks ties by frequency, so it would still read العلم as "knowledge" (both readings are definite nouns), and brings about 445 MB of model plus torch. Not met: a reading CAMeL has no fitting gloss for (تسكن "you live": CAMeL glosses سَكَن only "be calm"); see open question 3 |
| STT provider | Soniox real-time (`stt-rt-v6`) as the first adapter, with `max_endpoint_delay_ms` 1000; Deepgram Nova-3 kept as the fallback behind the same interface. Changed from Deepgram by spike #3 (`scripts/spikes/stt-msa/`). On 15.5 min of real class MSA, Soniox made 5.5% word errors (3.2% at its default setting) to Deepgram's 9.2%. It writes standard spelling and punctuation, where Deepgram writes no hamza, no ة and almost no punctuation. It lists at about $0.12/h to Deepgram's $0.46/h. The cost is latency: a final word's median wait for its gloss is 0.8-3.7 s, against Deepgram's 0.4-1.7 s, with a p95 of up to 7 s in long unbroken speech. Interim text trails the speaker by about 1 s, against 0.25 s |
| Sentence translation | Google Cloud Translation (Basic, v2), called once per finalized Utterance. The final Arabic shows at once and the translation fills in beneath it when it arrives; a failed translation leaves the Utterance untranslated and recording carries on. Per-word glosses come from the dictionary, not this service |
| STT cost | The learner's own keys, entered on the settings screen (see API keys (#13)); distribution model (BYO key vs proxy) deferred |
| Audio source | Mic plus system-audio loopback |
| Audio devices (#12) | The Settings screen's Audio section chooses what a Session records from, saved as each choice is made in `settings.json` in the app's data folder, beside the API keys (#13). **Desktop audio (transcribed)** is "All system audio" (WASAPI loopback, the default) or any audio input, such as Stereo Mix or a virtual audio cable: Windows loopback cannot record one output device, so the way to transcribe a single app or output is to route it to such an input. A chosen input is recorded without echo cancellation, noise suppression or automatic gain. **Microphone (Mic Track)** is the system default or a chosen input. A device is saved by id with its label, so one that is unplugged still shows ("not connected"), and starting a Session with it starts nothing and points to Settings. The Start panel names the devices the Session will use |
| API keys (#13) | The Settings screen holds a Soniox, a Deepgram and a Google Cloud Translation key. Each is stored in `settings.json`, encrypted with the system key store (Electron safeStorage, DPAPI on Windows); the renderer only ever learns whether a key is set, where from, and its last four characters. A key entered there wins over its environment variable (`SONIOX_API_KEY`, `DEEPGRAM_API_KEY`, `GOOGLE_TRANSLATE_API_KEY`, also read from the git-ignored dev `.env` outside packaged builds), which shows as set "by the environment" and cannot be removed there. A pasted key loses surrounding whitespace; one with inner spaces is refused. Saving a key checks it at once, and Check tries it again: Soniox lists its models, Deepgram lists its projects, Google translates one word. A refused key says where to get a working one (and, for Google, to enable the Cloud Translation API); no answer, a timeout, 429 or a 5xx says the service could not be reached and keeps the key. Speech-to-text takes the key in use when a Session starts (Soniox, else Deepgram); translation takes it per sentence. The Start panel warns when there is no speech-to-text key (audio only, no Transcript) or no translation key, linking to Settings |
| Resilience (#13) | Nothing but Stop ends a recording. When speech-to-text stops early (no key, a refused connection, a service error, a dropped stream, or the service ending the stream while recording), the Desktop and Mic Tracks keep every chunk, the Utterances already final stay, and Live View says transcription has stopped while the audio records, with the reason. The next Session tries again; a stopped stream is not reconnected within a Session. A failed translation (no key, offline, refused) leaves that Utterance in Arabic only, as before, and later Utterances are translated once it works again |

## Dictionary plan (v1, proposed)

Detail Modules and the source behind each. All data is looked up locally from one bundled SQLite file built by an offline build script, never from raw dumps at runtime.

| Detail Module | Source | Notes |
|---|---|---|
| Lemma, part of speech, root, pattern | CAMeL analyzer output (`lex`, `pos`, `root`, `pattern`) | Verified fields. Runs per Token in the sidecar |
| Quick gloss (shown under the word in Live View) | Wiktionary first sense, CAMeL `stemgloss` as fallback | Built (#8); rules under Decisions, Quick gloss. Reviewed on real transcripts, see open question 3 |
| Pronunciation | CAMeL `caphi` | Phonetic transcription, from the diacritized form |
| Full definitions, etymology, related forms | Wiktionary (English edition) via wiktextract/kaikki | Build script filters to Arabic entries and to forms we need. No licence stated on kaikki; Wiktionary text is CC BY-SA, so attribute |
| Example sentences (general) | Tatoeba AR-EN (about 31k pairs, CC BY 2.0) | Optional module; simple sentences |
| Your own examples | The learner's own Utterances | Built from Vocabulary history |
| Verb conjugation | Qutrub (GPL) or CAMeL generation | Decide later; not v1-critical |

Built (#9): the dictionary (schema 2) also keeps each entry's Wiktionary etymology and indexes every Tatoeba sentence by its words' letters, for the word panel's definitions and examples modules. A schema-1 file is refused; rebuild it. Measured: 14,424 of the 27,307 entries have an etymology (1.7 MB of text), and the word index holds 226,305 rows; **the built file is now 13.6 MB** (was 7.5 MB), and finding examples for the commonest words (في، من) takes about 24 ms.

Built (#8): `npm run build:dictionary` (`scripts/build-dictionary.mjs`) downloads kaikki.org's raw English-Wiktionary dump (`raw-wiktextract-data.jsonl.gz`, 3.08 GB, cached in the git-ignored `vendor/dictionary-sources/`) and Tatoeba's per-language `ara`/`eng` sentence exports with their `ara-eng` links. It streams the dump once (about 4 min) and writes `vendor/dictionary/dictionary.db` plus a `NOTICE.txt` with attribution; packaged builds are to ship that folder as `resources/dictionary`. Measured on the 30 Oct 2026 dump: of 233,417 Arabic entries, 27,307 are kept (12,833 nouns, 7,275 verbs, 3,798 adjectives, 2,384 names, the rest particles, pronouns, phrases); the 196,443 gloss-less root-form verb stubs, 8,836 inflection (form-of) and 1,071 alternative-spelling entries are dropped. Each kept entry holds its headword, part of speech and sense glosses. Tatoeba gives 48,663 Arabic-English pairs (more than the 31k Arabic sentences, since one can have several translations). **The built file is 7.5 MB.** Licences, confirmed: Wiktionary text is CC BY-SA 4.0 (also GFDL); kaikki.org states no licence of its own and asks for attribution to wiktextract (Ylonen, LREC 2022) and a link; Tatoeba is CC BY 2.0 FR. Both are recorded in the database's `meta` table and in `NOTICE.txt`, which the attribution screen should show.

Facts established: CAMeL provides `diac`, `lex`, `caphi`, `gloss`, `pos`, `root`, `pattern`, clitic fields and `stemgloss`. Kaikki's Arabic file is 827.9 MB (about 177k distinct word forms) but is marked **deprecated**; the supported source is the raw all-languages dump (2.9 GB compressed, 24.8 GB uncompressed). The build script should therefore extract Arabic entries from the raw dump once, or run wiktextract ourselves, and ship only the compact result.

## Installer size (researched)

Verified: CAMeL's MSA data is small: `morphology-db-msa-r13` 40.5 MB plus `disambig-mle-calima-msa-r13` 88.7 MB (both GPL v2), 129.2 MB together on disk. Install these two packages directly, **not** `camel_data -i light`: `light` also pulls every dialect database and MLE model plus the dialect-ID model (536 MB on disk). The large packages (AraBERT NER and sentiment 541.6 MB each, mBERT 712.5 MB) are not needed either.

Verified (spike #2, `scripts/spikes/camel-no-torch/`): `camel-tools` 1.6.0 declares `torch`, `transformers`, `scikit-learn`, `scipy`, `pandas` and `numpy` as hard requirements, but morphology plus MLE disambiguation **runs on Windows without any of them**. Install `camel-tools` with `--no-deps`, then only `cachetools`, `editdistance`, `emoji`, `regex`, `six`, `pyrsistent`, `tqdm`, `requests` and `muddler`. No vendoring needed. The wheels avoided total about 208 MB compressed (torch alone 126.7 MB).

Measured, Python helper (embeddable Python 3.13 + packages above + MSA data):

| Part | On disk |
|---|---|
| Embeddable Python runtime | 21.2 MB |
| site-packages | 9.2 MB |
| MSA data | 129.2 MB |
| **Helper total** | **159.7 MB** (23.8 MB zipped) |

Startup: about 2 s to import and 4 s to load the MLE model; disambiguating a sentence then takes milliseconds. So the helper runs as one long-lived process per app run, not one spawn per Utterance.

Packaging (decided by spike #2): ship the official Windows embeddable Python with a `site-packages` folder (camel-tools `--no-deps`, pinned) and a data folder holding only the two MSA packages, located through `CAMELTOOLS_DATA`. Electron spawns it as the sidecar. A build script fetches all three; the spike's `smoke.py`, which fails if any heavy package is imported, guards every camel-tools upgrade. Built (#6): `npm run build:helper` (`scripts/build-camel-helper.mjs`) writes the bundle to the git-ignored `vendor/camel-helper/`; packaged builds are to ship it as `resources/camel-helper`. The helper is `helper/camel/analyze.py`, speaking JSON lines over stdin/stdout.

Measured (#8): the dictionary SQLite (Wiktionary extract plus Tatoeba) is 7.5 MB; 13.6 MB since #9 added etymologies and the example word index. Estimate, unmeasured: Electron shell about 100-150 MB. With the 160 MB helper, the installed app is likely 270-320 MB, with no torch.
